# Phase 3: 통합 테스트 + 엣지 케이스 처리

## 목표
- Phase 1 + 2 결합 후 전체 시나리오 검증
- 엣지 케이스 발견 및 수정
- 성능 프로파일링

## 선행 조건
- Phase 1 완료 (ChatClient.cs 동작)
- Phase 2 완료 (ChatUIController.cs + 입력 시스템 가드)
- Chat Server + Room Server + Game Server 동시 기동 가능

## 작업 목록

### Task 1: 전체 생명주기 시나리오 테스트

- [ ] 시나리오 A — 로비 채팅:
  1. 클라이언트 2대 Chat Server 접속
  2. LOBBY 채널 메시지 송수신 확인
  3. 한 쪽 접속 해제 → 나머지 클라이언트 영향 없음

- [ ] 시나리오 B — 로비 → 인게임 전환:
  1. Room Server에서 방 생성 + 입장 + GameStart
  2. ChatClient 세션 재인증 자동 수행 확인 (sessionId + teamId 포함)
  3. TEAM 채널 메시지 — 같은 팀만 수신 확인
  4. ALL 채널 메시지 송수신 확인
  5. 히스토리 20개 수신 확인 (사전에 메시지 존재 시)

- [ ] 시나리오 C — 인게임 → 로비 복귀:
  1. 게임 종료 (OnGameOver)
  2. ChatClient 로비 모드 자동 복귀 확인
  3. LOBBY 채널 메시지 정상 동작 확인
  4. UI 채널 탭 자동 전환 확인

- [ ] (후순위) 시나리오 D — WHISPER:
  1. 인게임 상태에서 `/w 대상이름 메시지` 전송
  2. 대상에게만 메시지 도달 확인
  3. 발신자에게 에코 메시지 수신 확인
  4. 존재하지 않는 대상 → PLAYER_NOT_FOUND 에러 UI 표시

### Task 2: 재연결 시나리오

- [ ] Chat Server 강제 종료 → ChatClient 재연결 시도 (1s/2s/4s 백오프)
- [ ] 재연결 성공 후 자동 재인증 (로비 or 세션 모드)
- [ ] 3회 실패 후 OnDisconnected 이벤트 → UI "연결 끊김" 표시
- [ ] 재연결 중 사용자 메시지 전송 시도 → 적절한 에러 피드백

### Task 3: Rate Limit + 입력 검증

- [ ] 5초 내 10개 초과 메시지 전송 → RATE_LIMITED 에러 + UI 피드백
- [ ] 200 bytes 초과 메시지 → 클라이언트 사전 차단 확인 (서버 도달 전)
- [ ] 빈 메시지 / 공백만 → 전송 차단 확인
- [ ] 특수문자, 유니코드(한글, 이모지) 포함 메시지 정상 처리 확인

### Task 4: 성능 프로파일링

- [ ] 500+ 유닛 전투 중 채팅 메시지 10초 간격 송수신 → 프레임 드롭 측정
- [ ] ChatClient ReceiveLoop 메모리 할당 프로파일링 (GC spike 확인)
- [ ] ChatUIController ScrollRect 50개 메시지 갱신 시 UI 스레드 부하 측정
- [ ] 결과 기록: 허용 범위 (메인 루프 1ms 미만 추가 부하)

### Task 5: 발견된 버그 수정

- [ ] Task 1~4에서 발견된 버그 목록화
- [ ] 각 버그 수정 + 재검증
- [ ] 수정 사항 execution-log.md에 기록
