# 도착 판정 수정 — 통합 체크리스트

## Context

채집 시스템의 워커가 ResourceCenter 반납 시 도착 실패하는 버그가 확인되었다.

**실측 로그 (ResourceCenter 반납, FlowFieldSteeringSystem nearR 수정 후):**
```
dist=683 (6.83m, 워커 실제 정지 거리)
need=670 (6.70m, ObstacleRadius + WorkRange = 6.0 + 0.7)
→ 0.13m 부족, 영구 도착 실패
```

**분석 문서:** [Docs/Internal/Analysis/도착 판정 전수 검사.md](../../Internal/Analysis/도착%20판정%20전수%20검사.md)

## 근본 원인 분석

### 도착 판정 방식 비교

| 시스템 | 거리 방식 | 그리드 보정 | 상태 |
|--------|----------|------------|------|
| **BuildArrivalSystem** | XZ | `+ CellSize * 0.7` + 재시도 3회 | 마진 부족으로 간헐적 재시도 |
| **WorkerGatheringSystem** | **3D** | 없음 | **P0 실패 확인** |
| **RangedAttackSystem** | 3D | 없음 | 잠재적 문제 |
| **PredictedMovementSystem** | XZ | 없음 (이동 레벨) | 정상 |
| **MovementArrivalSystem** | XZ | 없음 (이동 레벨) | 정상 |

### 문제의 핵심: FlowField 셀 양자화 + 이동 도착 허용 오차

접근점(approach point)은 `center - direction * (ObstacleRadius + 0.1)` = center로부터 6.1m 지점이며, 그리드 blocked 영역(3.0m) 밖에 정상 위치한다. **접근점 자체는 문제없다.**

실제 원인은 **이동 시스템이 접근점에 정확히 정지하지 못하는 것**이다:

```
[접근점 설정]
  접근점 = center - dir * (ObstacleRadius + 0.1) = center - dir * 6.1m
  ArrivalRadius = (WorkRange - 0.1) * 0.5 = 0.3m

[이동 시스템의 도착 판정]
  FlowFieldSteeringSystem 인접 셀 스냅: nearR = obstacle.Radius = 0.5m
  MovementArrivalSystem 확장 반경 = ArrivalRadius * 2 = 0.6m (진동 감지)
  엔티티 Separation 밀림 ~0.2m
  → 워커가 접근점에서 최대 ~0.7m 떨어진 곳에서 정지 가능

[채집 시스템의 도착 판정]
  도착 거리 = ObstacleRadius + WorkRange = 6.0 + 0.7 = 6.7m
  접근점 거리 = 6.1m
  가용 마진 = 6.7 - 6.1 = 0.6m
  이동 오차 = ~0.7m
  → 0.6m < 0.7m → 도착 실패 (마진 근소 부족)
```

**오차 분해:**
| 요인 | 최대 오차 |
|------|----------|
| FlowFieldSteeringSystem 인접 셀 스냅 (nearR = obstacle.Radius) | 0.5m |
| MovementArrivalSystem 확장 반경 (2 * ArrivalRadius) | 0.6m |
| 엔티티 Separation 밀림 | ~0.2m |
| **합계 (독립 경로이므로 max)** | **~0.7m** |

> FlowFieldSteeringSystem 스냅과 MovementArrivalSystem 확장 반경은 독립 경로다. 스냅이 발동하면 waypoint이 현재 위치로 덮어써져 MovementArrivalSystem은 즉시 도착 판정한다. 따라서 합산이 아닌 max 기준으로 평가.

가용 마진(0.6m)이 이동 오차(~0.7m)와 근소한 차이로 부족하여 도착 실패가 발생한다.

**실측 (nearR 수정 후):**
```
dist=683 (6.83m)  need=670 (6.70m)  → 0.13m 부족, 영구 도착 실패
```

BuildArrivalSystem은 `+ CellSize * 0.7` 마진 + 재시도 3회로 이 문제를 우회하고 있다.

## 해결 전략

### 핵심 수정: CellSize 기반 마진 추가

BuildArrivalSystem과 동일한 패턴으로 도착 거리에 **CellSize 마진**을 추가한다.

```
// 기존 (WorkerGatheringSystem)
arrivalDist = ObstacleRadius + WorkRange                     = 6.0 + 0.7 = 6.7m

// 수정
arrivalDist = ObstacleRadius + WorkRange + CellSize          = 6.0 + 0.7 + 1.0 = 7.7m
                                                                7.55m < 7.7m → 도착 성공
```

BuildArrivalSystem은 `CellSize * 0.7` 마진 + 재시도 3회로 동작 중이나, 마진이 이동 오차(~1.5m)보다 부족하여 간헐적으로 재시도가 발생한다. 모든 도착 판정을 `CellSize * 1.0` 마진으로 통일하여 재시도 없이 **1회 도착 보장**한다.

### 부수 수정

1. **3D → XZ 거리 통일**: 이동 시스템(PredictedMovementSystem, MovementArrivalSystem)은 XZ 거리를 사용한다. 채집 시스템도 XZ로 통일하여 이동-상호작용 간 거리 판정 일관성 확보.

2. **ArrivalRadius 누락 보완**: `TransitionToReturn`과 `DecideNextAction`에서 ArrivalRadius를 설정하지 않는 문제 수정. MovementArrivalSystem이 ArrivalRadius를 리셋하지 않아 이전 값이 잔존하지만, 명시적 설정이 안전하다.

3. **BuildArrivalSystem CellSize 마진 통일**: `CellSize * 0.7` → `CellSize * 1.0`으로 변경. 재시도 로직은 안전망으로 유지하되, 마진 증가로 사실상 발생하지 않게 된다. (기존 마진 1.05m → 1.35m, 이동 오차 ~1.5m의 극단 케이스 외에는 1회 도착)

4. **effectiveRadius (미래 대비)**: 현재 모든 건물에서 `ObstacleRadius > gridBlockedHalfExtent`이므로 effectiveRadius가 실질적 효과 없음. 단, 향후 ObstacleRadius가 작은 대형 건물이 추가될 경우를 대비하여 접근점 계산에 안전장치로 적용.

### 현재 건물별 effectiveRadius 영향 분석

| 건물 | ObstacleRadius | gridBlockedHalfExtent | effectiveRadius | 변화 |
|------|---------------|----------------------|-----------------|------|
| Wall | 3.0 | 1.0 | 3.0 | 없음 |
| Barracks | 4.5 | 2.0 | 4.5 | 없음 |
| ResourceCenter | 6.0 | 3.0 | 6.0 | 없음 |
| OreVein | 6.0 | 3.0 | 6.0 | 없음 |

→ effectiveRadius는 현재 건물에서 ObstacleRadius와 동일. 접근점 위치 변화 없음. 미래 건물 안전장치 역할.

## 설계 결정

### ArrivalUtility에 CellSize 마진 포함 도착 거리 메서드 추가

```csharp
/// <summary>
/// FlowField 셀 양자화 + 이동 도착 허용 오차를 보정한 상호작용 도착 거리
/// 모든 상호작용 시스템(채집, 건설)에서 공통 사용
/// </summary>
[MethodImpl(MethodImplOptions.AggressiveInlining)]
[BurstCompile]  // primitive-only 파라미터
public static float GetGridCompensatedArrivalDistance(
    float targetRadius, float interactionRange, float cellSize)
{
    return targetRadius + interactionRange + cellSize;
}
```

### ArrivalUtility에 effectiveRadius 메서드 추가 (접근점 안전장치)

```csharp
/// <summary>
/// 그리드 차단 반경을 고려한 유효 반지름.
/// 접근점이 blocked 셀 밖에 배치되도록 보장.
/// 현재 모든 건물에서 ObstacleRadius가 이미 충분하여 실질적 변화 없음 (미래 대비).
/// </summary>
[MethodImpl(MethodImplOptions.AggressiveInlining)]  // in StructureFootprint → BC1064 방지, [BurstCompile] 불가
public static float GetEffectiveRadius(
    float obstacleRadius, in StructureFootprint footprint, float cellSize)
{
    int pathWidth = math.max(1, footprint.Width - 2);
    float gridBlockedHalfExtent = pathWidth * cellSize * 0.5f;
    return math.max(obstacleRadius, gridBlockedHalfExtent + cellSize * 0.5f);
}
```

```
Phase 1 (ArrivalUtility 확장)
  ↓ 도착 거리 메서드 + effectiveRadius 메서드 추가 완료
Phase 2 (GatheringSystem + BuildArrivalSystem 수정) — Phase 1 의존
  ↓ GetArrivalDistance → GetGridCompensatedArrivalDistance 사용
  ↓ BuildArrivalSystem도 동일 메서드로 통일
Phase 3 (접근점 보정) — Phase 1 의존
  ↓ CalculateApproachPoint가 effectiveRadius 사용
Phase 4 (테스트 + 문서) — Phase 1~3 완료 후
```

Phase 2와 Phase 3는 Phase 1 완료 후 병렬 진행 가능. Phase 4는 최후.

## 검증 방법

1. **ResourceCenter 반납**: 워커가 ResourceCenter 도착하여 자원 반납 성공 확인
2. **ResourceNode 채집**: 워커가 자원 노드 도착하여 채집 시작 확인
3. **자동 복귀**: 하차 후 자동으로 노드 복귀 + 재채집 사이클 확인
4. **건설 도착 개선**: BuildArrivalSystem 재시도 로그 미발생 확인 (마진 증가로 1회 도착)
5. **Burst 빌드**: 컴파일 에러 없음 확인
6. **EditMode 테스트**: ArrivalUtilityTests 통과 + 기존 테스트 통과
