# 별도 이슈: 건설 이동 목표가 blocked cell 위에 떨어져 건설 실패

## 증상

1. **건설 실패(giveup)**: 인접 건물이 있을 때 빌더가 도착 범위 내에 도달하지 못하고 즉시 포기
2. **건물 내부 진입**: 건설 성공 시에도 빌더가 건물 중앙에 너무 가깝게 이동하여 건물 생성 후 벽 충돌로 밀려남

## 원인

**HandleBuildMoveRequestSystem.cs:135-148**

```csharp
float3 toBuilder = builderPos - rpc.BuildSiteCenter;
float destinationOffset = rpc.StructureRadius + workRange * 0.5f;
goalRW.ValueRW.Destination = rpc.BuildSiteCenter + (toBuilder / dirLen) * destinationOffset;
```

FlowField 목표를 `BuildSiteCenter + offset` 방향으로 설정한다. 이 offset 지점이 **인접 건물의 blocked cell 위에 떨어지면** FlowField가 해당 지점에 도달할 수 없다.

### 실측 로그 (Wall 연속 건설)

```
BuildMove builder=(21,-1), site=(23,-9), dest=(22,-5), off=335
  → giveup pos=(21,-4), dist=517, need=469  (345ms 후, 이동 시도했으나 실패)

BuildMove builder=(21,-4), site=(23,-9), dest=(22,-5), off=335
  → giveup pos=(21,-4), dist=517, need=469  (15ms 후, 즉시 포기!)
```

15ms = 즉시 포기. `dest=(22,-5)` 지점이 인접 Wall의 blocked cell 위이므로 FlowField가 도달 불가 판정. 빌더가 이미 가장 가까운 passable cell `(21,-4)`에 있어 waypoints 즉시 비활성화 → BuildArrivalSystem이 사거리 밖 판정 → giveup.

## 핵심 제약

`MovementWaypoints.ArrivalRadius`는 `MovementWaypoints.Current`(현재 웨이포인트)와 비교되며, `MovementGoal.Destination`과는 비교되지 않는다. 따라서 ArrivalRadius를 크게 설정하는 것만으로는 빌더가 Destination에서 원하는 거리에 정지할 수 없다.

## 수정 방향

**FlowField 목표를 `BuildSiteCenter` 자체로 설정 (항상 passable) + `BuildApproachRadius` 컴포넌트로 정지 거리 제어.**

### 변경 파일

| 파일 | 변경 |
|------|------|
| `Shared/Components/Construction/BuildApproachRadius.cs` | **신규** — `IComponentData { float Value; }` |
| `HandleBuildMoveRequestSystem.cs` | Destination → BuildSiteCenter, ECB로 BuildApproachRadius 추가 |
| `FlowFieldSteeringSystem.cs` | BuildApproachRadius Lookup + 조기 정지 체크 |
| `BuildArrivalSystem.cs` | ECB로 BuildApproachRadius 제거 |

### 동작 변경

```
현재:
  Destination = BuildSiteCenter + offset  ← blocked cell 가능
  ArrivalRadius = 0.35m (waypoint 도착용)

수정 후:
  Destination = BuildSiteCenter           ← 항상 passable
  BuildApproachRadius = StructureRadius + workRange
  FlowFieldSteeringSystem: dist < BuildApproachRadius → 정지
  ArrivalRadius = 0.35m (변경 없음)
```

### 수치 검증 (Wall, StructureRadius=3.0)

```
stopDistance = 3.0 + 0.7 = 3.7m
FlowFieldSteeringSystem: dist < 3.7m → 정지
BuildArrivalSystem: arrivalDist = 3.0 + 0.7 + 1.0 = 4.7m
  → 3.7m < 4.7m ✓ (빌드 성공)
건물 생성 후: ObstacleRadius = 3.0m
  → 빌더 위치 3.7m > 3.0m ✓ (건물 밖, 밀림 없음)
```

### 설계 결정: 별도 컴포넌트 vs MovementGoal 필드 추가

MovementGoal에 `GoalArrivalRadius` 필드를 추가하면 Destination을 설정하는 16곳(7파일)에서 리셋이 필요하다. `BuildApproachRadius` 별도 컴포넌트는 건설 시에만 존재하고 건설 완료/포기 시 ECB로 제거되므로 stale value 문제가 없다.

## 우선순위

**높음**. 인접 건물이 있을 때 건설이 100% 실패하는 기능 결함. Wall 연속 건설 등 일반적 플레이 패턴에서 재현됨.
