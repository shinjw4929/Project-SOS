# 별도 이슈: 건설 시 빌더가 건물 중앙에 너무 가깝게 이동

## 증상

빌더가 건설 지점으로 이동할 때 건물이 배치될 영역 중앙 근처까지 진입한 뒤 건설을 수행한다. 건물이 생성되면 빌더가 건물 내부에 위치하게 되어 즉시 벽 충돌(GridObstacleResponseSystem)에 의해 밀려난다.

## 원인

**HandleBuildMoveRequestSystem.cs:139**

```csharp
float destinationOffset = rpc.StructureRadius + workRange * 0.5f;
```

건물이 아직 배치되지 않은 상태이므로 해당 영역에 grid blocked가 없다. FlowField가 정상적으로 경로를 생성하고, 빌더가 `StructureRadius + WorkRange * 0.5` 지점까지 이동한다.

문제는 `StructureRadius`가 건물 프리팹의 `ObstacleRadius` 값이 아니라 `BuildMoveRequestRpc.StructureRadius` (클라이언트에서 전달)인데, 이 값이 실제 건물의 grid blocked 반경보다 작을 수 있다는 점이다.

또한 `workRange * 0.5` = 0.35m는 FlowField 이동 오차를 고려하면 매우 작은 오프셋이다. 빌더가 건물 중심에서 `StructureRadius + 0.35m` 지점에 정지하면, 건물 생성 후 건물의 grid blocked 영역 안에 위치할 수 있다.

### 수치 예시 (Barracks)

```
StructureRadius = 4.5m
destinationOffset = 4.5 + 0.7 * 0.5 = 4.85m   (빌더 목표 거리)

건물 생성 후:
  grid blocked 반경 = max(1, 6-2) * 1.0 * 0.5 = 2.0m (셀 기반)
  ObstacleRadius = 4.5m
  → 빌더 위치(4.85m)는 ObstacleRadius(4.5m) 밖이지만
  → 이동 오차로 더 가까이 정지할 수 있음
  → 건물 Collider 범위 안에 위치 가능 → 벽 충돌로 밀려남
```

## 수정 방향

`destinationOffset`을 더 넉넉하게 설정하여 빌더가 건물 생성 후에도 안전한 위치에 있도록 한다.

```csharp
// 현재:
float destinationOffset = rpc.StructureRadius + workRange * 0.5f;

// 개선안:
float destinationOffset = rpc.StructureRadius + workRange;
```

`workRange * 0.5` → `workRange`로 변경하면 오프셋이 0.35m → 0.7m으로 증가하여 이동 오차(~0.7m)를 흡수할 수 있다.

## 우선순위

중간. 기능적으로 건설은 성공하지만, 건설 직후 빌더가 밀려나는 시각적 문제가 발생한다. 도착 판정 수정(ArrivalFix)과 독립적이며 별도로 처리 가능.
