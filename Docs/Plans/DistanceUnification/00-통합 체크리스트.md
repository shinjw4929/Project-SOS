# 거리/크기 단위 통일 리팩토링 — 통합 체크리스트

## Context

유닛, 적, 건물, 자원에서 크기/거리/범위 관련 필드가 혼재되어 있다.

**현재 크기 관련 개념 (정리 전):**
- Grid Size (Width/Length) — 그리드 셀 단위
- Pathfinding Size (PathWidth/PathLength) — 그리드 셀 단위
- World Size (WorldWidth/WorldLength/WorldHeight) — 월드 단위
- Shape (IsCircular/WorldRadius) — 월드 단위
- Interaction Radius (interactionRadius → ObstacleRadius) — 월드 단위
- Arrival Radius (MovementWaypoints.ArrivalRadius) — 월드 단위
- Unit Size (GridPathfindingSize.CellPadding) — enum (Small/Large)
- Physics Collider — 프리팹 GameObject에서 자동 베이킹

**목표**: 그리드를 단일 진실 소스(Single Source of Truth)로 확립하고, 파생 가능한 필드를 모두 제거하여 StructureFootprint를 최소화한다. 물리 충돌을 그리드 기반으로 통일한다.

## 현재 상태 분석

### 엔티티별 Authoring 필드 (크기/거리 관련만)

**StructureAuthoring (11개 필드):**
```
[Grid Size]        width(int=2), length(int=2), height(float=1)
[Pathfinding Size] pathWidth(int=2), pathLength(int=2)
[World Size]       worldWidth(float=1), worldLength(float=1), navMeshHeight(float=1)
[Shape]            isCircular(bool=false), navMeshRadius(float=1)
[Interaction]      interactionRadius(float=1) → ObstacleRadius
```

**ResourceNodeAuthoring (11개 필드):**
```
[Grid Size]        width(int=2), length(int=2), height(float=1)
[Pathfinding Size] pathWidth(int=2), pathLength(int=2)
[World Size]       worldWidth(float=1), worldLength(float=1), navMeshHeight(float=1)
[Shape]            isCircular(bool=true), navMeshRadius(float=1.5)
[Interaction]      interactionRadius(float=1.5) → ObstacleRadius
```

**UnitAuthoring (1개 필드):**
```
[Unit Size]        radius(float=1.0) → ObstacleRadius
```

**EnemyAuthoring (1개 필드 + aggroRange):**
```
[Collision]        radius(float=1.5) → ObstacleRadius
[Aggro]            aggroRange(float=15) → EnemyChaseDistance
```

**MovementAuthoring (2개 필드):**
```
[Pathfinding]      ArrivalRadius(float=0.5) → MovementWaypoints.ArrivalRadius
[Pathfinding Size] PathfindingSize(byte=0) → GridPathfindingSize.CellPadding
```

## 설계 결정

### 핵심 원칙: "그리드 = 단일 진실 소스"

SC1 방식 채택: 건물의 물리적 크기는 **그리드 셀 점유**로 정의하고, 모든 충돌/경로탐색/push-out을 그리드에서 파생한다. 원형 건물 충돌은 없다 (push-out 항상 직사각형). 유닛의 원형 접근은 ObstacleRadius가 담당 (별도 독립 필드).

### CellSize 0.5m → 1.0m 전환

그리드 셀 크기를 1.0m으로 변경. Width/Length 값은 그대로 유지하고, 건물 물리 크기를 2배로 확대.

- `GridSettingsAuthoring.cellSize`: 0.5f → **1.0f**
- `GridUtility.ResourceNodeExclusionDistance`: 18 → **9** (9m 거리 유지)
- 하드코딩된 `const float CellSize = 0.5f` → **1.0f** (Baker, System 등)
- 프리팹 Width/Length 값: **변경 없음** (동일 셀 수, 물리 크기만 2배)
- 비주얼 모델: 사용자 수동으로 2배 스케일 조정

| 프리팹 | Width | 물리 크기 (Before) | 물리 크기 (After) | PathWidth |
|--------|-------|-------------------|-------------------|-----------|
| Wall | 4 | 2m×2m | **4m×4m** | 2 (edge case 없음) |
| Barracks | 6 | 3m×3m | **6m×6m** | 4 |
| ResourceCenter | 8 | 4m×4m | **8m×8m** | 6 |
| OreVein | 8 | 4m×4m | **8m×8m** | 6 |

**장점**: FlowField BFS 4배 빠름 (40,000→10,000 셀), 캐시 메모리 4배 절감, Width=셀수=미터수로 직관적.
**ObstacleRadius, SpatialHash 셀 크기(10m/3m)**: 그리드 독립, 변경 없음.

### StructureFootprint 단일 소스 모델

```
Authoring 입력 (3개 필드):
  Width (int)      — 그리드 셀 단위 (배치 + 충돌 경계의 유일한 정의)
  Length (int)     — 그리드 셀 단위
  Height (float)   — 월드 단위

시스템에서 파생 (저장하지 않음):
  PathWidth       = max(1, Width - 2)        // 경로탐색 차단 (중앙 영역)
  PathLength      = max(1, Length - 2)
  PushHalfW       = Width * CellSize / 2     // 건설 시 유닛 밀어내기
  PushHalfL       = Length * CellSize / 2

제거 (8개 필드):
  PathWidth, PathLength    → 규칙 기반 파생 (Width - 2)
  WorldWidth, WorldLength  → Width * CellSize로 대체
  WorldHeight              → 미사용 확인됨 (GridObstacleResponseSystem에서 미참조)
  WorldRadius              → 직사각형 통일로 불필요
  IsCircular               → 제거 (모든 push-out 직사각형)
  navMeshRadius            → IsCircular 제거로 불필요
```

### PathWidth = max(1, Width - 2) 규칙

모든 건물에 1셀 통과 가능 테두리 적용 (SC1 스타일):
- Small 유닛(CellPadding=0): 건물 가장자리 1셀 통과 가능
- Large 유닛(CellPadding=1): 패딩으로 테두리 차단 → 통과 불가

| 프리팹 | Width | PathW (현재) | PathW (신규: W-2) | 변경 |
|--------|-------|-------------|-------------------|------|
| Wall | 4 | 2 | 2 | 변경 없음 |
| Barracks | 6 | 6 | 4 | 테두리 통과 가능 |
| ResourceCenter | 8 | 8 | 6 | 테두리 통과 가능 |
| OreVein | 8 | 8 | 6 | 테두리 통과 가능 |

### Collider 역할 재정의

| 용도 | Before | After |
|------|--------|-------|
| 벽 충돌/미끄러짐 (PredictedMovementSystem) | Physics Collider (CastRay, PointDistance) | **그리드 셀 기반 충돌** |
| 건설 시 유닛 push-out (GridObstacleResponseSystem) | StructureFootprint WorldWidth/Radius | **Width × CellSize 직사각형** |
| 유닛/건물 선택 (EntitySelectionSystem) | Physics Collider CastRay | 유지 |
| 우클릭 대상 탐지 (UnitCommandInputSystem) | Physics Collider CastRay | 유지 |
| 건설 위치/충돌 검증 | Physics Collider | 유지 |
| 투사체 충돌 (CombatDamageSystem) | Physics Trigger | 유지 |

Collider는 **raycast(선택, 건설)와 투사체 전용**. 물리 충돌(벽 미끄러짐, push-out)은 그리드 기반.

### 결정 요약

| 항목 | Before | After | 근거 |
|------|--------|-------|------|
| **CellSize** | **0.5m** | **1.0m** | BFS 4배 빠름, Width=미터수로 직관적 |
| StructureFootprint 필드 | 11개 | **3개** (Width, Length, Height) | 그리드 = 단일 소스, 나머지 파생 |
| Structure Authoring 필드 | 11개 | **4개** (Width, Length, Height, ObstacleRadius) | 8개 필드 제거 |
| Resource Authoring 필드 | 11개 | **4개** | 동일 |
| IsCircular | 건물별 원형/박스 분기 | **제거** (모든 push-out 직사각형) | SC1 방식, ObstacleRadius가 원형 접근 담당 |
| PathWidth/PathLength | 수동 설정 | **max(1, Width-2) 파생** | 전체 건물 반투과 테두리 통일 |
| WorldWidth/Length/Height/Radius | 수동 설정 | **제거** (그리드에서 파생) | 그리드 단일 소스 |
| 벽 충돌 (PredictedMovementSystem) | Physics CastRay/PointDistance | **그리드 셀 충돌** | 물리 의존성 제거, 단일 소스 |
| Unit/Enemy 필드명 | `radius` | `obstacleRadius` | 컴포넌트명 일치 |
| ArrivalRadius | 수동 설정 (0.5f) | **제거** (fallback 사용) | ObstacleRadius + 0.1f로 충분 |
| Enemy 추적 거리 | VisionRange + EnemyChaseDistance | **VisionRange 단일** | 이탈거리 = VisionRange × 1.3 |
| 투사체 속도 | Authoring(20f) + Utility(30f) | **Authoring 단일** | CombatUtility.ProjectileSpeed 제거 |

### Phase 2: 벽 충돌 그리드 전환 (PredictedMovementSystem)

**목표**: PredictedMovementSystem의 Physics 기반 벽 충돌을 그리드 셀 기반으로 교체. Physics 의존성 제거.

**현재 동작:**
```
ResolveWallCollision:
  [1] CastRay (이동 방향 벽 감지) → 속도에서 벽 법선 성분 제거 (미끄러짐)
  [2] PointDistance (주변 벽 감지) → 겹침 시 밀어내기
ClampToWall:
  [3] PointDistance ×3회 → 이동 후 관통 보정 (안전망)
모두 CollisionWorld + Layer 6,7 필터
```

**신규 동작:**
```
그리드 셀 충돌:
  [1] 이동 후 위치 ± ObstacleRadius가 path-blocked 셀과 겹치는지 체크
  [2] 겹침 시 최소 침투 축(X 또는 Z) 방향으로 밀어내기
  [3] 속도에서 벽 법선 성분 제거 (미끄러짐, 항상 축 정렬)
```

건물이 모두 축 정렬(axis-aligned) 직사각형이므로 벽 법선은 항상 ±X 또는 ±Z. Physics CastRay보다 단순.

- [ ] `PredictedMovementSystem.cs`: `ResolveWallCollision` 메서드를 그리드 셀 기반으로 재구현
- [ ] `PredictedMovementSystem.cs`: `ClampToWall` 메서드를 그리드 셀 기반으로 재구현
- [ ] `PredictedMovementSystem.cs`: `CollisionWorld`, `wallFilter` 관련 코드 제거
- [ ] `PredictedMovementSystem.cs`: GridSettings + GridCell 버퍼 접근 추가
- [ ] 유닛/적 속도 보존 로직 유지 (유닛: 속력 보존, 적: 벡터 삭제)
- [ ] path-blocked 셀 판정에 PathWidth 파생 규칙 적용: `max(1, Width - 2)` 기반

> **정밀도**: 0.5m 셀 경계에서 충돌 판정. 건물이 모두 축 정렬이므로 Physics 대비 정밀도 손실 없음. 대각선 벽이 없으므로 법선 계산도 단순.

## 검증 방법

1. **push-out 동작**: 건물 건설 시 내부 유닛이 그리드 경계 밖으로 밀려나는지 확인
2. **벽 미끄러짐**: 그리드 기반 벽 충돌에서 유닛이 벽을 따라 자연스럽게 미끄러지는지 확인
3. **반투과 테두리**: Barracks/RC/OreVein에서 Small 유닛이 가장자리 통과, Large 유닛 차단 확인
4. **원형 접근**: ObstacleRadius 기반 도착 판정이 기존과 동일하게 동작하는지 확인
5. **프리팹 값 보존**: `[FormerlySerializedAs]` 적용 후 Inspector에서 기존 값 유지 확인
6. **Enemy 행동**: VisionRange 통합 후 추적/이탈 거리 확인 (visionRange 값 조정 필수)
7. **투사체**: 물리/시각 투사체 속도 동일 확인
8. **Burst 빌드**: 컴파일 에러 없음 확인
9. **PlayMode 테스트**: 기존 테스트 통과
