# Project-SOS 3단계 로깅 시스템 구축 계획

## Context

현재 Project-SOS는 로깅이 전혀 없는 상태다. 모든 `Debug.Log` 호출이 주석 처리되어 있고, 로깅 정책도 미정의 상태. 멀티플레이 RTS 게임 특성상 전투/Wave/네트워크/경제 이벤트 추적이 필요하며, 프로덕션 환경에서 문제 진단과 게임 밸런싱 데이터 수집을 위해 체계적인 로깅 파이프라인이 필요하다.

## Tier 1: Unity 내부 로컬 파일 로깅 (`com.unity.logging`)

### 1-1. 패키지 설치
- `Packages/manifest.json`에 `"com.unity.logging": "1.3.4"` 추가
- `com.unity.collections: 2.6.3` 이미 설치되어 있으므로 호환성 문제 없음
- **주의**: `WriteTo.File` 확장 메서드는 `Unity.Logging.Sinks` 네임스페이스에 위치

### 1-2. Assembly Reference 추가

| asmdef | 추가할 Reference | 사유 |
|--------|-----------------|------|
| `Shared.asmdef` | `Unity.Logging` | GameLogger 유틸리티가 Shared에 위치 |
| `Server.asmdef` | (불필요) | Shared 경유 접근 |
| `Client.asmdef` | (불필요) | Shared 경유 접근 |

`GameBootStrap.cs`는 기본 Assembly-CSharp에 있으므로 별도 참조 불필요.

### 1-3. Logger 초기화 위치: `GameBootStrap.Initialize()`

`com.unity.logging`의 `Log` 클래스는 전역 static이므로, World 생성 전에 1회 설정하는 것이 적합. `base.Initialize()` 호출 전에 LoggerConfig 설정.

**주의사항**:
- `GameBootStrap.Initialize()`는 World 생성 전에 1회 실행된다
- Editor에서는 Client/Server World가 동일 프로세스에 공존하므로, 단일 로그 파일 사용. Server/Client 구분은 로그 메시지 접두사로 처리
- `Logger` 타입이 `Unity.Logging.Logger`와 `UnityEngine.Logger` 사이에 모호하므로 `Unity.Logging.Logger`로 정규화 필요

```csharp
// GameBootStrap.cs - Initialize() 내부, base.Initialize() 호출 전
using Unity.Logging;
using Unity.Logging.Sinks;

public override bool Initialize(string defaultWorldName)
{
    // ... 기존 설정 ...

    // --- 로깅 초기화 ---
    string logDir = Path.Combine(Application.persistentDataPath, "Logs");
    Directory.CreateDirectory(logDir);
    string logPath = Path.Combine(logDir, $"game_{DateTime.UtcNow:yyyyMMdd_HHmmss}.log");

    var config = new LoggerConfig()
        .MinimumLevel.Set(LogLevel.Info)
        .WriteTo.File(logPath,
            minLevel: LogLevel.Debug,
            maxFileSizeBytes: 10 * 1024 * 1024,
            maxRoll: 5)
        .WriteTo.UnityDebugLog(minLevel: LogLevel.Warning);

    Log.Logger = new Unity.Logging.Logger(config);

    Application.quitting += () =>
    {
        Log.FlushAll();
        Log.Logger?.Dispose();
    };
    // --- 로깅 초기화 끝 ---

    return base.Initialize(defaultWorldName);
}
```

**파일 경로 전략**:
- Windows: `%APPDATA%/LocalLow/{CompanyName}/Project-SOS/Logs/`
- 파일명: `game_{timestamp}.log` (단일 파일, world type 구분은 메시지 접두사로)
- 파일 로테이션: 10MB당 롤링, 최대 5개 유지 (총 50MB 상한)

### 1-4. 새 파일

#### `Assets/Scripts/Shared/Logging/LogCategory.cs`

```csharp
namespace Shared
{
    public enum LogCategory : byte
    {
        Combat = 0,     // 전투: 데미지, 사망, 타겟팅
        Movement = 1,   // 이동: 경로 탐색, 도착
        Network = 2,    // 네트워크: RPC, 접속, 연결 해제
        Economy = 3,    // 경제: 자원, 생산, 인구수
        Wave = 4,       // Wave: 전환, 스폰
        System = 5      // 시스템: 초기화, 부트스트랩, 오류
    }

    public enum LogWorld : byte { Server = 0, Client = 1 }
}
```

#### `Assets/Scripts/Shared/Logging/GameLogger.cs`

Burst 호환 static 유틸리티. `CombatUtility.cs`와 동일한 패턴.

**Burst BC1064 규칙 적용**:
- `GetPrefix`: `FixedString32Bytes` 반환(struct by value) → `[BurstCompile]` 제거, `[MethodImpl(AggressiveInlining)]`만 사용
- `Info/Warning/Error`: struct를 `in`(readonly ref)으로 받으므로 `[MethodImpl(AggressiveInlining)]` 사용
- 클래스 레벨 `[BurstCompile]`은 유지 (CombatUtility 패턴 동일)

**World 출처 구분**: Server/Client 시스템에서 호출 시 world type을 전달하여 `[S:Combat]`/`[C:Combat]` 식 접두사 생성.

```csharp
[BurstCompile]
public static class GameLogger
{
    [MethodImpl(MethodImplOptions.AggressiveInlining)]
    public static FixedString32Bytes GetPrefix(LogWorld world, LogCategory category) { ... }

    [MethodImpl(MethodImplOptions.AggressiveInlining)]
    public static void Info(LogWorld world, LogCategory category, in FixedString128Bytes message) { ... }

    [MethodImpl(MethodImplOptions.AggressiveInlining)]
    public static void Warning(LogWorld world, LogCategory category, in FixedString128Bytes message) { ... }

    [MethodImpl(MethodImplOptions.AggressiveInlining)]
    public static void Error(LogWorld world, LogCategory category, in FixedString128Bytes message) { ... }

    [MethodImpl(MethodImplOptions.AggressiveInlining)]
    public static void InfoWithValue(LogWorld world, LogCategory category, in FixedString64Bytes label, int value) { ... }
}
```

### 1-5. 로그 포인트 추가 대상 시스템 (우선순위 순)

| 우선순위 | 시스템 | 카테고리 | 레벨 | 로그 내용 |
|---------|--------|---------|------|----------|
| 1 | `WaveManagerSystem` | Wave | Info | Wave 전환 (시간/킬수 조건) |
| 2 | `HeroDeathDetectionSystem` | Combat | Warning | Hero 사망 |
| 3 | `GoInGameServerSystem` + `GoInGameClientSystem` | Network | Info | 클라이언트 접속 (Server/Client 양측) |
| 4 | `DamageApplySystem` | Combat | Info | 프레임당 킬 집계 (개별 공격 X) |
| 5 | `HandleBuildRequestSystem` | Economy | Info | 건설 요청 |
| 6 | `HandleProduceUnitRequestSystem` | Economy | Info | 유닛 생산 요청 |
| 7 | `PathfindingSystem` | Movement | Warning | 경로 계산 실패 시만 (5초 윈도우 집계) |
| 8 | `EnemySpawnerSystem` | Wave | Debug | 스폰 이벤트 |

**성능 원칙**: 매 프레임 대량 발생하는 이벤트(개별 공격 히트, 이동 틱)는 로깅하지 않는다. 상태 전환/집계 이벤트만 로깅.

## Tier 2: MongoDB — 포렌식 분석 저장소

> 상세 내용은 [로깅 Tier2 MongoDB.md](로깅%20Tier2%20MongoDB.md) 참조

### 핵심 요약

- **용도**: 개별 레코드 조회 + 원인 추적 ("이 엔티티 왜 벽 뚫었나")
- **저장 대상**: CommandTrail, 게임 정합성 오류, 코드 레벨 에러
- **스키마**: 중첩 Document (entity 상태 + command_trail 배열 + context)
- **수집**: Vector Agent가 Tier 1 로컬 파일을 tail → parse → MongoDB sink
- **보존**: TTL 인덱스 90일 자동 삭제

## Tier 3: ClickHouse + Grafana — 집계/추이 분석

> 상세 내용은 [로깅 Tier3 ClickHouse Grafana.md](로깅%20Tier3%20ClickHouse%20Grafana.md) 참조

### 핵심 요약

- **용도**: 빌드 간 위반 비율 비교, 실시간 대시보드, 알림
- **스키마**: 플랫 MergeTree 테이블 (LowCardinality 최적화)
- **수집**: Vector fan-out (MongoDB와 동시 전송, 별도 ETL 불필요)
- **대시보드**: Violation Overview, Build Comparison, Entity Analysis, Error Dashboard
- **알림**: 빌드 회귀 200% 초과, WallPenetration 5분 10건, 에러 5분 50건

## 전체 아키텍처

```
[Unity Server/Client Build]
    ECS Systems → GameLogger → com.unity.logging → FileSink (로컬 파일)
                                                      ↓ tail + parse
                                                 [Vector Agent]
                                            (내장 디스크 버퍼 + fan-out)
                                                 ↓               ↓
                                           [MongoDB]        [ClickHouse]
                                        중첩 Document       플랫 스키마
                                        포렌식 조회          집계/추이
                                        CommandTrail            ↓
                                                          [Grafana]
                                                       대시보드/알림
```
