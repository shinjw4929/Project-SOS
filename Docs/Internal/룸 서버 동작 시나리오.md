# 룸 서버 동작 시나리오

## 사전 조건

- Room Server (C++): `:8080` (public) + `:8081` (internal) 실행 중
- Game Server (Unity): `:7979` 실행 중 (AutoConnectPort = 0)
- Unity Client: Play 모드 진입 시 RoomClient가 `:8080`에 자동 접속

---

## 정상 흐름

### 시나리오 1: 방 생성 → 참가 → 게임 시작

```
[Client A]
1. Play → ConnectingPanel 표시 → Lobby 전환
2. 닉네임 + 방 이름 입력 → Create Room 클릭
3. RoomPanel 전환, 유저 목록에 자신 표시 ([HOST])

[Client B]
4. Play → Lobby 진입
5. Refresh → 방 목록에 Client A의 방 표시
6. Join 클릭 → RoomPanel 전환

[Client A, B]
7. 각자 Ready 클릭 → 상태 "READY" 표시

[Client A (호스트)]
8. Start Game 클릭

[양쪽 클라이언트]
9. GameStartingPanel → 게임 서버 접속
10. TokenValidationSystem 검증 통과 → Hero 생성
11. UI 숨김 → 게임 플레이
```

**확인 포인트:**
- [ ] Lobby에서 방 목록이 표시되는가
- [ ] 방 생성/참가 후 RoomPanel로 전환되는가
- [ ] 유저 목록에 호스트 뱃지, 준비 상태가 표시되는가
- [ ] 게임 시작 후 Hero가 생성되는가
- [ ] 서버 로그에 "Token validated" 메시지가 있는가

## 거부/에러 흐름

### 시나리오 3: 만석 방 참가

```
1. Client A가 max_players=2 방 생성
2. Client B 참가 (2/2)
3. Client C가 같은 방에 Join 시도
4. → RejectResponse(ROOM_FULL) → "Room is full" 표시
```

**확인 포인트:**
- [ ] 거부 메시지가 UI에 표시되는가
- [ ] Lobby 상태가 유지되는가 (패널 전환 없음)

### 시나리오 4: 미준비 상태에서 시작

```
1. Client A(호스트) + Client B가 대기실에 있음
2. Client B가 Ready를 누르지 않은 상태
3. Client A가 Start Game 클릭
4. → RejectResponse(NOT_ALL_READY) → "Not all players are ready" 표시
```

### 시나리오 5: 토큰 없이 게임 서버 직접 접속

```
1. 별도 Netcode 클라이언트로 :7979에 직접 연결 시도
2. GoInGameRequestRpc에 빈 토큰 전송
3. → TokenValidationSystem 검증 실패 → 즉시 Disconnect
```

**확인 포인트:**
- [ ] 서버 로그에 "Token validation failed" 메시지가 있는가
- [ ] 클라이언트가 Disconnect 되는가

## 연결 장애 흐름

### 시나리오 6: 룸 서버 접속 실패 + 재시도

```
1. 룸 서버를 실행하지 않은 상태에서 클라이언트 Play
2. ConnectingPanel 표시
3. 3회 재시도 (1초, 2초, 4초 간격)
4. 전부 실패 → ErrorPanel 표시 "Failed to connect..."
5. 룸 서버 시작 후 Retry 버튼 클릭
6. → 연결 성공 → Lobby 전환
```

**확인 포인트:**
- [ ] 로그에 재시도 시도가 3회 기록되는가
- [ ] ErrorPanel이 표시되는가
- [ ] Retry 후 정상 접속되는가

### 시나리오 7: 대기 중 룸 서버 강제 종료

```
1. Client가 Lobby 또는 대기실에 있는 상태
2. 룸 서버 프로세스 강제 종료 (kill)
3. → RoomClient가 연결 끊김 감지 → 자동 재접속 시도
4. 룸 서버 재시작
5. → 재접속 성공 → Lobby 복귀
```

**확인 포인트:**
- [ ] 로그에 "Unexpected disconnect, attempting reconnection" 메시지가 있는가
- [ ] 룸 서버 재시작 후 자동으로 Lobby에 복귀하는가

### 시나리오 8: 게임 중 클라이언트 연결 끊김

```
1. 정상 흐름으로 게임 진입
2. 클라이언트 프로세스 강제 종료 (또는 네트워크 차단)
3. → 게임 서버 SlotNotifySystem이 ConnectionState.Disconnected 감지
4. → SlotReleased(userId, sessionId) 전송
5. → 룸 서버가 슬롯 해제
```

**확인 포인트:**
- [ ] 게임 서버 로그에 "SlotReleased sent" 메시지가 있는가
- [ ] 룸 서버에서 해당 세션이 정리되었는가

## 재플레이 흐름

### 시나리오 9: 게임 종료 후 로비 복귀

```
1. 정상 흐름으로 게임 진입 + 플레이
2. 게임 종료 조건 발생 (Hero 사망 등)
3. RoomClient.OnGameOver() 호출
4. → RoomAuthState 초기화 (토큰 제거)
5. → 룸 서버 재접속 → Lobby 복귀
6. 새 방 생성 가능
```

**확인 포인트:**
- [ ] Lobby로 정상 복귀하는가
- [ ] 새 방 생성/참가가 가능한가

## 타임아웃/TTL 흐름

### 시나리오 10: 토큰 만료 (60초 TTL)

```
1. GameStart 수신 후 게임 서버 접속을 의도적으로 지연 (60초 초과)
2. GoInGameRequestRpc 전송
3. → TokenValidationSystem: 룸 서버 검증 실패 (토큰 만료)
4. → Disconnect
5. → 클라이언트 자동 재접속 → Lobby 복귀
```

### 시나리오 11: 게임 서버 비정상 종료

```
1. 게임 진행 중 게임 서버 프로세스 강제 종료
2. → SlotReleased 전송 안 됨, GameServerHeartbeat 중단
3. → 룸 서버 TTL 90초 만료 → 해당 서버 세션 전체 자동 정리
```

**확인 포인트:**
- [ ] 90초 후 룸 서버에서 세션이 정리되었는가

### 시나리오 12: 호스트 이탈 (대기실)

```
1. Client A(호스트) + Client B 대기실
2. Client A가 Leave 또는 연결 끊김
3. → 룸 서버: 방 삭제 → ROOM_CLOSED 전송
4. → Client B: "Room has been closed" 표시 → Lobby 복귀
```

## 하트비트 검증

### 클라이언트 → 룸 서버 (10초 간격)

```
1. Lobby 또는 대기실 상태에서 10초 대기
2. 로그 또는 룸 서버 측에서 RoomHeartbeat 수신 확인
```

### 게임 서버 → 룸 서버 (30초 간격)

```
1. 게임 진행 중 30초 대기
2. 게임 서버 로그에서 heartbeat 전송 확인
3. 룸 서버 측에서 GameServerHeartbeat 수신 확인
```
