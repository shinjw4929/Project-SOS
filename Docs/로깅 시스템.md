# 로깅 시스템

## 전체 흐름

```
[Bootstrap] GameBootStrap.Initialize() (World 생성 전, 1회 실행)
├─ 일자별 로그 폴더 생성 (Logs/yyyy-MM-dd/)
├─ LoggerConfig 설정
│   ├─ FileSink: Debug 이상 → 파일 기록 (10MB × 5 롤링)
│   └─ UnityDebugLog: Warning 이상 → Unity 콘솔 출력
├─ Log.Logger 할당 (com.unity.logging)
├─ 30일 초과 폴더 삭제 (CleanOldLogs)
└─ Application.quitting → FlushAll + Dispose

[Runtime] 각 시스템에서 GameLogger 호출
├─ GameLogger.Debug/Info/Warning/Error(LogWorld, LogCategory, message)
├─ GetPrefix → [S:Category] 또는 [C:Category]
└─ FixedString128Bytes 메시지 → FixedString512Bytes(prefix+msg) → Log.Info() 등

[출력] com.unity.logging 내부 처리
├─ FileSink → persistentDataPath/Logs/yyyy-MM-dd/game_HHmmss.log
└─ UnityDebugLog → Unity Console (Warning 이상만)
```

## 핵심 설계 포인트

1. **com.unity.logging 기반**: Burst Job 내에서도 로깅 가능 (`Unity.Logging.Log`는 Burst 네이티브 지원)
2. **BC1064 방지**: GameLogger 클래스 `[BurstCompile]`, 개별 메서드 `[MethodImpl(AggressiveInlining)]` (struct 파라미터/반환 시 `[BurstCompile]` 불가)
3. **FixedString 파이프라인**: 호출부에서 `FixedString128Bytes`로 메시지 조립 → GameLogger 내부에서 `FixedString512Bytes`에 prefix 결합 → `Log` API 호출
4. **헬퍼 메서드**: `Field(ref msg, key, value)`, `Pos(ref msg, key, float3)`로 수동 Append 반복 제거
5. **일자별 폴더 + 30일 보관**: 게임 시작 시 1회 정리, 런타임 부하 없음

## 초기화 (GameBootStrap.cs)

| 항목 | 설정 |
|------|------|
| MinimumLevel | `LogLevel.Info` |
| FileSink minLevel | `LogLevel.Debug` |
| FileSink 로테이션 | 10MB/파일, 최대 5개 롤링 (세션당 50MB 상한) |
| UnityDebugLog minLevel | `LogLevel.Warning` |
| 로그 경로 | `Application.persistentDataPath/Logs/{yyyy-MM-dd}/game_{HHmmss}.log` |
| 보관 기간 | 30일 (CleanOldLogs에서 초과 폴더 삭제) |
| 종료 처리 | `Application.quitting` → `Log.FlushAll()` + `Log.Logger?.Dispose()` |

## 로깅 래퍼 (Shared/Logging/)

| 파일 | 역할 |
|------|------|
| LogCategory.cs | `LogCategory` enum (Combat, Movement, Network, Economy, Wave, System) + `LogWorld` enum (Server, Client) |
| GameLogger.cs | Burst 호환 로깅 래퍼. `[BurstCompile]` 클래스, `[MethodImpl(AggressiveInlining)]` 메서드. Debug/Info/Warning/Error + Field/Pos 헬퍼 |

### GameLogger API

| 메서드 | 용도 |
|--------|------|
| `Debug(LogWorld, LogCategory, in FixedString128Bytes)` | 파일에만 기록 |
| `Info(LogWorld, LogCategory, in FixedString128Bytes)` | 파일에만 기록 |
| `Warning(LogWorld, LogCategory, in FixedString128Bytes)` | 파일 + 콘솔 |
| `Error(LogWorld, LogCategory, in FixedString128Bytes)` | 파일 + 콘솔 |
| `Field(ref msg, key, int)` | 메시지에 `, key=value` 추가 |
| `Field(ref msg, key, FixedString32Bytes)` | 메시지에 `, key=value` 추가 (문자열) |
| `Pos(ref msg, key, float3)` | 메시지에 `, key=(x,z)` 추가 |

### 사용 예시

```csharp
FixedString128Bytes msg = "Build retry";
GameLogger.Field(ref msg, "idx", entity.Index);
GameLogger.Field(ref msg, "try", retryCount);
GameLogger.Pos(ref msg, "pos", unitPos);
GameLogger.Pos(ref msg, "site", buildSite);
GameLogger.Info(LogWorld.Server, LogCategory.Economy, in msg);
// 출력: [S:Economy] Build retry, idx=12, try=1, pos=(8,15), site=(10,18)
```

## 파일 경로

```
{persistentDataPath}/
└── Logs/
    ├── 2026-03-15/
    │   ├── game_144512.log        ← 현재 세션
    │   ├── game_144512.log.1      ← 롤링 1 (10MB 초과 시)
    │   └── game_160000.log        ← 다른 세션
    ├── 2026-03-14/
    │   └── game_120000.log
    └── 2026-02-13/                ← 30일 초과 → 시작 시 삭제
```

| 플랫폼 | persistentDataPath |
|--------|-------------------|
| Windows | `C:\Users\{user}\AppData\LocalLow\{CompanyName}\{ProductName}\` |
| macOS | `~/Library/Application Support/{CompanyName}/{ProductName}/` |
| Linux | `~/.config/unity3d/{CompanyName}/{ProductName}/` |

## 성능 원칙

1. **매 프레임 대량 발생 이벤트**: 로깅하지 않음 (개별 공격 타격, 이동 틱 등)
2. **상태 전환 이벤트**: 로깅 (Wave 전환, 접속, 건설 성공)
3. **집계 이벤트**: 시간 윈도우 기반 집계 후 로깅 (경로 실패 5초 윈도우)
4. **빈도 높은 이벤트는 Debug**: 프로덕션에서 MinimumLevel을 Info로 올리면 자동 필터링
