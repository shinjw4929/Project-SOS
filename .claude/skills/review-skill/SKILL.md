## 역할

스킬 SKILL.md 파일을 검토하여 토큰 효율성, 기존 스킬과의 중복, 프로젝트 적합성을 점검하고 개선안을 제시한다.

$ARGUMENTS가 있으면 스킬명 또는 경로로 해석한다. 없으면 `.claude/skills/*/SKILL.md`를 전체 스캔하여 요약 리포트를 출력한다.

## 검토 절차

### 1단계: 대상 확정 및 데이터 수집

1. $ARGUMENTS가 스킬명이면 `.claude/skills/[$ARGUMENTS]/SKILL.md`를 읽는다.
2. $ARGUMENTS가 경로이면 해당 파일을 읽는다.
3. $ARGUMENTS가 없으면 `.claude/skills/*/SKILL.md`를 Glob으로 수집하여 전체 스캔 모드로 진행한다.

`.claude/skills/SKILLS.md`도 읽어 전체 스킬 목록과 계층 구조를 파악한다.

$ARGUMENTS에서 스킬명/경로 외 추가 텍스트가 있으면 추가 검토 관점으로 반영한다.

### 2단계: 검토 에이전트 실행

Agent를 호출하여 검토를 수행한다. `subagent_type: "general-purpose"`. 워크트리 격리 불필요 (읽기 전용).

에이전트 프롬프트에 1단계에서 수집한 데이터(스킬 파일 전문, SKILLS.md 전문, 추가 검토 관점)를 포함한다.

**개별 스킬 검토 시** 에이전트 지시:
```
당신은 Claude Code 스킬 파일 검토 전문가입니다.

## 검토 대상
[1단계에서 수집한 스킬 파일 전문]

## 전체 스킬 목록
[SKILLS.md 전문]

## 지시사항
다음 4개 관점에서 순차 검토한다.

A. 토큰 효율성
- `wc -c`로 파일 크기 측정 (5KB 이하 권장, 6KB 이상 경고)
- `wc -l`로 줄 수 측정 (200줄 이하)
- 본문에서 `Docs/` 경로 추출 → `wc -c`로 크기 확인 (10KB 이상 경고)
- `/스킬명` 패턴 추출 → auto-call 체인 깊이 확인 (2단계 이상 경고)
- 같은 문서를 여러 단계에서 읽는 절차가 있는지 확인

B. 기존 스킬 중복
- SKILLS.md에서 전체 스킬 목적(description)과 비교
- 동일 입력→출력, 기존 스킬 확장으로 대체 가능한지 판단

C. 프로젝트 적합성
- allowed-tools 최소화 (수정 없으면 Edit/Write 제외)
- Tier 배치 적절성
- 프론트매터 형식 (name: kebab-case, description: 한국어 1줄)
- 한국어 작성, 출력 템플릿 코드 블록 존재 여부

D. 구조 품질
- $ARGUMENTS 처리 (파싱 + fallback)
- 단계별 절차 명확성
- 주의사항 섹션 존재
- 단일 목적 수행

## 반환 형식 (이 형식만 반환)
## 스킬 검토 결과: {스킬명}
### 토큰 효율성
| 항목 | 값 | 판정 |
### 기존 스킬 중복
| 유사 스킬 | 중복 영역 | 판정 |
### 프로젝트 적합성
| 항목 | 판정 | 비고 |
### 구조 품질
| 항목 | 판정 |
### 개선안
| # | 항목 | 현재 | 제안 | 이유 |
### 최종 판정
(적합 / 개선 필요 / 재설계 필요)
```

**전체 스캔 시** 에이전트 지시:
```
당신은 Claude Code 스킬 파일 검토 전문가입니다.

## 대상
[Glob으로 수집한 스킬 경로 목록]

## 지시사항
각 스킬에 대해 `wc -c`와 `wc -l`을 실행한다.
토큰 효율성(A)만 전체 스킬에 적용하여 요약 테이블을 출력한다.
경고 기준을 넘는 스킬만 상세 검토 대상으로 표시한다.

## 반환 형식 (이 형식만 반환)
## 전체 스킬 토큰 효율성 스캔
| 스킬 | 크기 | 줄 수 | auto-call | 대형 참조 | 판정 |
### 경고 대상
- {스킬명}: {사유}
### 최적화 제안
- ...
```

### 3단계: 결과 출력

에이전트 결과를 그대로 출력한다.

## 주의사항

- **읽기 전용**: 이 스킬은 코드나 스킬 파일을 수정하지 않는다. 개선안만 제시한다.
- **사실 기반**: 파일 크기, 줄 수, 참조 경로 등 측정 가능한 데이터로만 판단한다.
- **과잉 지적 금지**: 기준치 이내인 항목은 "Pass"로 처리하고 상세 설명을 붙이지 않는다.
