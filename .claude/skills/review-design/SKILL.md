## 역할

코드 변경 또는 구현 계획이 `Docs/GameDesign.md`에 정의된 기획 방향성과 일치하는지 검증한다.
코드 수정은 하지 않는다. 검증 결과만 출력한다.

$ARGUMENTS가 있으면 해당 내용을 검증 대상/관점으로 반영한다.

## 검증 절차

### 0단계: 기획 방향성 로드

`Docs/GameDesign.md`를 읽어 현재 기획 방향성을 파악한다.
문서가 없거나 비어있으면 사용자에게 알리고 중단한다.

### 1단계: 검증 대상 파악

검증 대상을 다음 순서로 결정한다:

1. **$ARGUMENTS가 플랜 경로/기능명**: 해당 계획의 orchestration.md + phase 파일을 읽는다.
2. **$ARGUMENTS가 구체적 설명**: 해당 내용을 검증 대상으로 삼는다.
3. **$ARGUMENTS 없음**: `git diff HEAD`로 현재 코드 변경사항을 검증 대상으로 삼는다.

### 2단계: 기획 방향성 대조

검증 대상을 GameDesign.md의 각 섹션과 대조한다:

| 검증 항목 | GameDesign.md 기준 | 위반 예시 |
|-----------|-------------------|-----------|
| **게임 컨셉** | 협동 웨이브 디펜스, 순수한 재미 | PvP 요소 추가, 과도한 복잡성 |
| **협동 설계** | 자발적 협동, 보금자리 메카닉 | 강제 협동, 협동 없이도 최적인 설계 |
| **벽 시스템** | 벽은 무적, 방어선 구축이 핵심 | 벽에 HP 추가, 벽 파괴 메카닉 |
| **공간 점유** | 유닛/적/벽/자원노드는 밀리지도 겹치지도 않음 | 엔티티 간 겹침 허용, 밀어내기 물리 |
| **유닛 설계** | 역할 삼각 구조, 만능 유닛 없음 | 모든 역할을 수행하는 유닛, 역할 구분 모호 |
| **적 디자인** | 웨이브별 크기 감소/공중 등장/물량 증가 | 후반에 대형만 등장, 물량 감소 |
| **경제 시스템** | 자원 충분하되 시간 부족, 벽 vs 유닛 투자 선택 | 자원 과잉으로 선택 무의미, 최적 빌드 고정 |
| **조작 설계** | QWER + 좌우클릭, APM 불필요 | 복잡한 단축키 추가, 빠른 조작이 유리한 설계 |
| **게임 페이스** | 평균 5~10분, 최대 20분 | 30분 이상 걸리는 설계 |
| **감정 곡선** | 긴장→안도→위기→대응→긴박→결판 | 단조로운 난이도, 중반 지루함 |
| **설계 원칙** | 10장에 명시된 원칙들 | 원칙 위반 |

### 3단계: 검증 결과 출력

```
## 기획 방향성 검증 결과

### 검증 대상
- (코드 변경 / 구현 계획 / 구체적 설명)

### 일치 항목
- (기획 방향성과 부합하는 부분)

### 불일치 항목
| # | 기획 원칙 | 현재 구현/계획 | 불일치 내용 | 심각도 |
|---|-----------|---------------|-------------|--------|
| 1 | ...       | ...           | ...         | 위반/주의 |

### 미확인 항목
- (기획 문서에 아직 정의되지 않아 판단 불가한 부분)

### 최종 판단
(기획 부합 / 기획 불일치 / 기획 미정의)
```

**심각도 기준**:
- **위반**: 기획 방향성에 명시적으로 반하는 구현 (예: 벽에 HP 부여)
- **주의**: 기획 의도와 미묘하게 어긋날 수 있는 구현 (예: 특정 유닛이 너무 범용적)

### 4단계: 후속 안내

- **기획 부합**: 결과만 출력하고 종료.
- **기획 불일치**: 위반 항목을 나열하고, 기획에 맞는 대안을 제안한다. 코드 수정이 필요하면 직접 수정하지 않고 사용자에게 안내한다.
- **기획 미정의**: GameDesign.md에 해당 영역의 기획을 추가할 것을 권장한다.

## 주의사항

- **기획 문서가 최우선**: 코드가 기획과 다르면, 기획이 맞는지 코드가 맞는지 판단하지 않는다. 불일치 사실만 보고하고 사용자가 판단한다.
- **코드 수정 금지**: 이 스킬은 검증만 수행한다. 수정이 필요하면 사용자에게 안내한다.
- **과잉 해석 금지**: GameDesign.md에 명시적으로 기술된 내용만 기준으로 삼는다. 문서에 없는 기획 의도를 추측하지 않는다.
- **미정의 영역 존중**: "차후 추가 예정"으로 표시된 영역은 위반으로 판단하지 않고 "미정의"로 분류한다.
