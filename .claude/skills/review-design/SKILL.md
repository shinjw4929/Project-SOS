## 역할

코드 변경 또는 구현 계획이 `Docs/GameDesign.md`에 정의된 기획 방향성과 일치하는지 검증한다.
코드 수정은 하지 않는다. 검증 결과만 출력한다.

$ARGUMENTS가 있으면 해당 내용을 검증 대상/관점으로 반영한다.

## 검증 절차

### 1단계: 검증 대상 데이터 수집

검증 대상을 다음 순서로 결정하고 데이터를 수집한다:

1. **$ARGUMENTS가 플랜 경로/기능명**: 해당 계획의 orchestration.md + phase 파일을 읽는다.
2. **$ARGUMENTS가 구체적 설명**: 해당 내용을 검증 대상 텍스트로 보관한다.
3. **$ARGUMENTS 없음**: `git diff HEAD`와 `git diff HEAD --name-only`로 현재 코드 변경사항을 수집한다.

수집한 데이터(diff 전문, 계획 내용, 또는 설명 텍스트)를 에이전트 프롬프트에 포함할 변수로 보관한다.

### 2단계: 워크트리 격리 에이전트 실행

Agent를 호출하여 검증을 수행한다. 반드시 다음 파라미터를 설정:
- `isolation: "worktree"` — 워크트리 격리 (필수)
- `subagent_type: "general-purpose"`
- `description: "기획 방향성 검증"`

에이전트 프롬프트 구조:
```
당신은 게임 기획 정합성 검증 전문가입니다.

## 검증 대상
[1단계에서 수집한 데이터]

## 지시사항
1. Docs/GameDesign.md를 읽어 현재 기획 방향성을 파악한다. 문서가 없으면 "기획 문서 없음"을 반환.
2. 검증 대상을 GameDesign.md의 각 섹션과 대조: 게임 컨셉, 협동 설계, 벽 시스템, 공간 점유, 유닛 설계, 적 디자인, 경제 시스템, 조작 설계, 게임 페이스, 감정 곡선, 설계 원칙.
3. 코드 품질/성능은 판단하지 않는다. 오직 기획 의도와의 정합성만 본다.
4. GameDesign.md에 명시되지 않은 내용은 추측하지 않는다.
5. "차후 추가 예정" 영역은 위반이 아닌 "미정의"로 분류한다.

## 심각도 기준
- 위반: 기획 방향성에 명시적으로 반하는 구현
- 주의: 기획 의도와 미묘하게 어긋날 수 있는 구현

## 반환 형식 (이 형식만 반환)
## 기획 방향성 검증 결과
### 검증 대상
- (코드 변경 / 구현 계획 / 구체적 설명)
### 일치 항목
- ...
### 불일치 항목
| # | 기획 원칙 | 현재 구현/계획 | 불일치 내용 | 심각도 |
### 미확인 항목
- ...
### 최종 판단
(기획 부합 / 기획 불일치 / 기획 미정의)
```

### 3단계: 결과 출력 및 후속 안내

에이전트 결과를 그대로 출력한다.

- **기획 부합**: 결과만 출력하고 종료.
- **기획 불일치**: 위반 항목을 나열하고, 기획에 맞는 대안을 제안한다. 코드 수정이 필요하면 직접 수정하지 않고 사용자에게 안내한다.
- **기획 미정의**: GameDesign.md에 해당 영역의 기획을 추가할 것을 권장한다.

## 주의사항

- **기획 문서가 최우선**: 코드가 기획과 다르면, 기획이 맞는지 코드가 맞는지 판단하지 않는다. 불일치 사실만 보고하고 사용자가 판단한다.
- **코드 수정 금지**: 이 스킬은 검증만 수행한다. 수정이 필요하면 사용자에게 안내한다.
- **과잉 해석 금지**: GameDesign.md에 명시적으로 기술된 내용만 기준으로 삼는다. 문서에 없는 기획 의도를 추측하지 않는다.
- **미정의 영역 존중**: "차후 추가 예정"으로 표시된 영역은 위반으로 판단하지 않고 "미정의"로 분류한다.
